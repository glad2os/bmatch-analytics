# bmatch-analytics

Аналитика сыгранной партии BubbleMatch. Сервис берёт реплей из таблицы `game_replays`, которую пишет
gameserver после завершённой игры, и для каждого живого игрока считает пять метрик и предложение по
изменению MMR. Запускается вручную.

## Запуск

Из `bmatch-deployment`:

```bash
docker compose run --rm analytics list                 # последние партии: uuid, игроки, разобрана ли
docker compose run --rm analytics <game_uuid>          # посчитать и показать, ничего не пишет
docker compose run --rm analytics <game_uuid> --save   # сохранить результат в game_analytics
docker compose run --rm analytics <game_uuid> --apply  # сохранить и прибавить изменение к users.mmr
```

Флаг `--json` выводит машиночитаемый результат. `--include-autoplay` засчитывает игроку ходы,
сделанные автоматически после `debug end`, — чтобы проверить весь путь до профиля на debug-игре.
Такой результат помечается как debug и autoplay и никогда не меняет MMR. `--apply` для каждой пары (игра, игрок) срабатывает
один раз: уже применённая строка не пересчитывается и MMR второй раз не меняется. Gameserver держит
профили (вместе с MMR) в кэше Redis до часа, так что в лобби и игре новый MMR появится не сразу. Без docker:
`npm ci && PGHOST=… PGUSER=… PGPASSWORD=… PGDATABASE=bmatch node src/cli.js <game_uuid>`.

Тесты: `npm test`.

## Что оценивается

Лог событий проигрывается целиком: каждая открытая клетка, кто бы её ни открыл (бот тоже), становится
известна всем за столом. Оцениваются только ходы людей. Ходы ботов, в том числе бота, занявшего место
вышедшего игрока, и все ходы после `debug end` (их делает логика бота) не разбираются, а только
обновляют знание о поле. Для вышедшего игрока считаются ходы до выхода.

Попытка — это два выбора клетки за ход. Пара оставляет ход за игроком, и следующая попытка начинается
сразу.

Все метрики нормированы на число возможностей, а не на партию, иначе игру с тремя ботами, открывающими
много клеток, нельзя было бы сравнить с игрой двух людей. Каждая метрика — число от 0 до 1 или `null`,
если в партии не было возможности её измерить.

| Метрика | Как считается |
|---|---|
| **Memory** | Доля использованных шансов вспомнить. Шанс есть, если перед первым выбором на поле была известная пара или если первая клетка показала картинку, вторую клетку с которой уже видели. Использовал — открыл эту пару. Дополнительно: средний и максимальный «возраст» вспомненной клетки (сколько открытий прошло с момента, когда её видели). |
| **Accuracy** | Качество решений без учёта везения. Для каждой попытки: шанс найти пару, который дали выборы игрока, делённый на лучший шанс в той же позиции. Известная пара = 1. Неизвестная клетка = `K/U + (U−K)/U · 1/(U−1)`, где U — неоткрытые клетки, K — открытые клетки без известной пары. Вторая клетка верна, если это известная пара первой, а если пары не знали — любая ещё не открытая. Открыть заведомо не ту клетку (wasted probe) или не открыть известную пару — 0. Таймаут — 0. Для справки выводятся hit rate (пары / попытки), пары «наугад», wasted probes, таймауты. |
| **Speed** | Медиана времени на выбор: от начала хода (или от предыдущей пары или первой клетки) до открытия. Паузы вычитаются, таймаут = 30 с. Шкала логарифмическая: 0,8 с и быстрее = 1, 30 с = 0. |
| **Streaks** | После найденной пары ход остаётся у игрока: доля таких случаев, когда следующая попытка тоже дала пару. Дополнительно: самая длинная серия и число серий из 2 и более пар. |
| **Consistency** | Ровность игры, нужно не меньше 6 оценённых попыток. Среднее двух величин: `1 − (max − min)` средних Accuracy по третям партии и `1 − MAD/медиана` времени на выбор. |

## MMR

Изменение зависит от того, как человек сыграл, а не от фиксированных ± за победу или поражение:

```
P     = взвешенное среднее метрик: Memory 0.30, Accuracy 0.30, Speed 0.15, Streaks 0.10, Consistency 0.15
        (веса неизмеренных метрик делятся между остальными)
E     = 0.5 + 0.35 · tanh((mmr − 2000) / 600)        ожидаемый P при текущем рейтинге
conf  = min(1, попытки / 12)                          короткая партия двигает рейтинг меньше
ΔMMR  = round(40 · (P − E) · conf)
```

Сыграл выше своего уровня — рейтинг растёт, ниже — падает. Чем выше рейтинг, тем больше от игрока
ожидается. Особые случаи:

- Debug-игры не рейтинговые: для справки выводится, каким было бы изменение.
- Вышедший раньше времени: если изменение отрицательное, оно считается с conf = 1, чтобы выход не
  уменьшал потерю. Положительное считается как обычно.
- Нет ни одной попытки — изменения нет.

Данных о реальных игроках пока нет, поэтому константы — первое приближение. Каждая сохранённая строка
содержит все сырые метрики и `model_version`, так что модель можно перекалибровать и пересчитать.

## Таблица

`game_analytics (game_uuid, player_id, username, metrics jsonb, performance, mmr_before, mmr_delta,
rated, model_version, computed_at, applied_at)`, первичный ключ `(game_uuid, player_id)`. Сервис
создаёт таблицу сам при первом запуске.
